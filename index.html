How Samvad works

The same pipeline runs for any corpus you add.

  1. 1
    Chunk the corpus. Split the source into small, self-contained passages with a lightweight structural prefix (chapter, speaker, section), so retrieval has the context it needs.
  2. 2
    Embed and index. Encode every chunk with a sentence-transformer, store the unit-normalised vectors in FAISS for fast cosine search.
  3. 3
    Retrieve. A metadata router catches exact references ("verse 2.47") first; everything else goes through top-k vector search, optionally filtered by chapter or section.
  4. 4
    Ground the answer. Pass the retrieved passages to Claude with strict instructions: cite only these, refuse when they don't cover the question. Every citation is verified against what was retrieved.
  5. 5
    Stream it. Tokens flow to the UI as they arrive. Sources appear first, the answer builds in real time, and a final event replaces streamed text with cleanly scrubbed output.

What makes it trustworthy

Six choices that keep Samvad honest.

Inline citations

Every claim ends with a (chapter.verse) tag. Open the source carousel to read the actual passage word for word.

Confidence floor

If retrieval scores below 0.3 similarity, the model refuses rather than guessing. No forced answers from weak context.

Post-hoc verification

After the model replies, every cited verse is checked against what was retrieved. Hallucinated citations are flagged, not hidden.

Measurement baseline

A fixed-question regression suite runs against the pipeline and writes an eval scorecard. Any change shows up as a diff.

Multilingual presentation

For the Gita, every verse surfaces Devanagari, IAST, and English together. Each layer is optional per source.

Streaming by default

Answers stream token by token, so you see the reasoning build up instead of staring at a spinner.
